4.1 **Introduction**

&#x09;4.1.1 *The Shortest Path Problem:* 

&#x09;	The shortest path problem deals with finding the path between two vertices on some domain (like a graph) where the sum of the weights between them are 				minimized.  These weights can describe cost, distance, time, or anything of the like; the goal remains the same.  

&#x09;4.1.2 *Applicability of Dijkstra's Algorithm*

&#x09;	Dijkstra's Algorithm was designed to solve these single-source-shortest-path problems, working to minimized the distance (weight, cost, etc) from one node to 			all other nodes in the domain (ie graph).  It works on directed or undirected graphs alike, but all weights must be non negative.  

&#x09;4.1.3 *Non-Negative Edge Requirement*

&#x09;	Dijkstra's Algorithm is a **greedy algorithm**, which means once the vertex or node is marked as visited, then it just marks that as the shortest path to the node 			from the previous nodes.  If the algorithm allowed use of negative weights, the distance summed between two nodes would be reduced and breaking the core 			function of the algorithm. 

&#x09;4.1.4  *Relaxation* 	

&#x09;	Described by dist\[v] > dist\[u] + cost (u,v) , where *u* is the visted node and *v* is the unvisited node.  The algorithm will update summed weight values if the 			expression holds, further minimizing costs as it progresses.  

&#x09;4.1.5 *Data Structure Role*

&#x09;	Dijkstra's Algorithm is typically implemented with priority queue (min heap) to track all unvisited vertices with the minimum distance from the source vertex.  	This comes with a time complexity of O(**log V**), where v is the number of vertices.
